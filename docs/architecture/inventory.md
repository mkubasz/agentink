# dark-factory inventory for Ink Hub (Phase 0)

- **Fork point:** `kacperwerema/dark-factory` at `8aa85c6` (v0.59.0, 2026-10-31); module `github.com/michal-franc/issue-viewer`, Go 1.25.
- **Read on:** 2026-11-01, four read-only passes over the tree (the issue domain, the viewer, the agent runtime and the CLI, the remaining packages), every claim cited as `path:line` at the fork point.
- **Purpose, as written:** map every code area to an Ink Hub context with one verdict — **keep / rework / park / drop** — and a reason, so a strangler migration would have a ledger.
- **Purpose, after Q0 (2026-11-01, the owner: "piszemy od zera"):** Ink Hub is a clean-room rebuild (ADR 0003) and **no code from this inventory is carried over**. Read the verdicts as: *keep* and *rework* = a concept Ink Hub reimplements from the spec flow's formats and its own contracts; *park* and *drop* = not taken. The `path:line` citations are references to behaviour, kept so a reviewer can check a claim about what dark-factory does; they are not an invitation to open those files while writing Ink Hub code (provenance rule 1).

## 1. Verdicts

| Verdict | Meaning | What happens to the code |
|---|---|---|
| **keep** | Ink Hub uses it as-is, possibly moved | must build and pass its tests at every commit |
| **rework** | the concept survives; the code is ported into a slice or extracted into a shared package | stays until the slice replaces its last caller (ADR 0003) |
| **park** | untouched until the owner decides | builds; its tests run in the legacy tier |
| **drop** | candidate for removal | removed only after the owner accepts the verdict, in its own commit |

"Candidate" is the operative word for *drop*: the owner's acceptance is recorded in the commit that removes the code and in this file.

### 2.1 The failing root-package tests

The root package's suite depends on tmux and on a stand-in `claude` binary. Red in this sandbox (`go test . -count=1`, 205 s):

| Test | Time | Cause |
|---|---|---|
| `TestStartAgentSession_TypingDuringDispatchCannotChangeTheStartCommand` | 91 s | tmux-driven agent start; the stand-in never shows the prompt |
| `TestStartAgentSession_CtrlCOnTheAgentKeepsTheWindow` | 16 s | same family |
| `TestNewcomerWalkthrough` | 42 s | "the stand-in agent never started" after the tmux session was created (`newcomer_test.go:266`) |
| `TestSystemPage_RowsCarryCardMarkers` | 0.05 s | `handlers_workboard_test.go:339: system page rows: missing needs revision · D-5` — not environmental: a page-model regression present at the fork point |

The other 46 packages are green. Three of the four reds are environmental (tmux + a stand-in agent); one is a real regression in the viewer's system page and is **park** like the page itself (not fixed in Phase 0, recorded here). **Consequence for ADR 0003:** the legacy tier (`make test-legacy`) needs tmux and a stand-in agent on the machine that runs it, and "green" is defined as this baseline: `go test ./... -count=1 -skip '^(TestStartAgentSession_TypingDuringDispatchCannotChangeTheStartCommand|TestStartAgentSession_CtrlCOnTheAgentKeepsTheWindow|TestNewcomerWalkthrough|TestSystemPage_RowsCarryCardMarkers)$'`. Ink Hub's own CI must not depend on tmux.

## 6. Mechanisms to port, by context

### 6.1 platform/eventlog — the seed and what it lacks
Seed on `internal/memory/events.go`: `locked(fn)` (:196-206) → `readEvents` (:167-193) → check → `appendEvents` (one `O_APPEND` write of N marshalled lines, :209-231), `History(id)` from the retained events (:113-156), `rewrite` tmp + rename for compaction (:234-253). Take from `internal/outputs/outputs.go` the skip-and-report `BadLine{Line, Err}` (:299-307) instead of memory's fail-whole-load (`events.go:188`), and the log-order tie-break `seq[id]` (:287, :317-322); from `internal/critique/store.go` the later-line-amends-earlier-by-id event (:42-46, :147-150). None of the six JSONL logs has `rev`, `subject`, `causation_id`/`correlation_id`, a per-project file or a `type` field (they use `op`); time is inconsistent (`RFC3339Nano` strings `outputs.go:490`, `RFC3339` strings compared lexicographically `events.go:104,255`, `time.Time` with local offsets `store.go:19`). The platform log fixes all of that in one envelope (ADR 0005). Lock: `telemetry.LockFile` (`store.go:120-133`, flock polled every 2 ms) or `queue.Update`'s flock (`queue.go:158-191`), extracted as `platform/lock`.

### 6.2 inbox — from "Needs you" to a projection
`needsYouRowsWith` (`needs_you.go:110-150`) merges seven sources into `WbQueueCard{Kind, Label, Project, Slug, Title, Note, Age, CTA, URL, Blocking, Since, Tone, Target, Ready}` (`workshop.go:169-193`), ordered `Blocking` first then oldest `Since` (`map.go:190-197`); `Since` falls back to the file mtime and is flagged `Approx` (`attention.go:146-154`); cross-project aggregation runs one goroutine per project with a per-project error row (`needs_you.go:287-333`). The inbox projection keeps: kind, project, subject, title, since, blocking, ready; drops: shelf, jobs, connectors, bug reports. `stationMove` (`station.go:517-586`) orders the owner's steps on one issue (question → playtest → checks → stamp) and is the model for the order of pages in `00-inbox.pdf`. The clarify form's `Expect` guard (`clarify_view.go:184`, `tracker/clarify.go:541-543`: refuse when the question's *text* changed since the form was built) is the model for the question revision: Ink Hub's `rev` is the hash of the question's text and options, not of the file (ADR 0005).

### 6.3 inbox — answer kinds and their grammars
| Kind | Today | Written as |
|---|---|---|
| clarify answer | `AnswerQuestion` `tracker/clarify.go:520-574` | `**Answer:** <n> · <date> · owner: "<words>" (D-k)` + a `D-k` line under `## Decisions` (`decisions.go:182-201`) |
| approval (stamp) | `stampApproval` `handlers_issue_mutate.go:362-400`, `writeApproval` `cmd_approve.go:104-118` | frontmatter `human_approval`, comment `approval: "<words>" (<how>, <date>) → <status>` (`approval_comment.go:26-32`), stats `last_approval` |
| rejection (send back) | `handleSendBack` `send_back.go:319-373` | comment `rejected: "<words>" (<how>, <date>) → back to <status>` or `→ stays in <status>` (`tracker/send_back.go:116-122`) |
| confirm a provisional decision | `ConfirmDecision` `decisions_confirm.go:101-146` | the same `D-n` line rewritten with the quote and `confirmed by owner <date>` |

### 6.4 agents — what the adapter replaces
The tmux surface is in §5.3's table. The delivery policies to settle once: `issue-cli lead message` refuses to paste into a Claude session (`cmd_lead.go:506-507`, "use SendMessage") while the viewer's approval nudge pastes into any worker (`root tmux.go:18-20`, `agentrun.Nudge` :409-435). For Ink Hub: herdr `agent.prompt` (refuses a blocked agent with `agent_blocked`; `--wait` reports `agent_prompt_stalled`), rex `rex send` then `rex send-key enter` (verified: `rex send` does not press Enter), headless `claude -p --resume <session>` — which needs a session id that nothing records at launch today (`ceo_transcript.go:22-29` reads transcripts instead). Health probe: `routing.FindLimit` (`limits.go:58-70`) on any text. Identity at `ink ask` time: `whoAmI` (`lead_live.go:81-113`: env, then tmux, then cwd) extended with `HERDR_PANE_ID`/`HERDR_WORKSPACE_ID`/`HERDR_TAB_ID` and `REX_SESSION`/`REX_BLOCK`/`REX_SERVER`.

### 6.5 pages — the four owner-facing formats
- **critique**: `blocks|should|note <path>:<line>[-end][,more] — <text>` (`internal/critique/format.go:137-159`), `Coverage:` and `Not read:` lines (:198-221); fixtures with six real runs in `internal/critique/testdata/spec-flow-runs.jsonl`. The page shows one finding per row with a ✓/✗ zone and a reason field.
- **stamp**: a box is the owner's when `(owner)` appears outside quotes or the line starts `Owner <check|review|decides…>` (`tracker/ownermark.go:24-45`); agents never tick it (`proof/ownerbox.go:50-68`). The page is one large YES/NO zone plus a signature zone; the answer is an `approval:` or `rejected:` line.
- **proposals**: `- [ ] A<n>: <title>` with `Differently:`, `Place:`, `Text:` (`postmortem.go:42-48,91-97`); one box per action; `Decide` applies the agreed ones (`apply.go:62-125`).
- **escalation**: `QuestionText` (`redrounds.go:181-195`) with its three options; the page's zones are "try X / skip / stop" plus a note, as the brief says.

### 6.6 specflow — writing a spec file safely
Atomic write and single-file commit: `gitfile.WriteAtomic` (`gitfile.go:157-175`) and `gitfile.Commit` with its `old`-bytes compare-and-swap (`ErrStale` :21, :39-41). Two things to change: the mutex is in-process (:17-18), so a cross-process lock (`queue.Update`'s flock, `queue.go:158-191`, or `tracker.withIssueLock`'s `O_EXCL` sidecar, `issue.go:188-208`) wraps it; and `Commit` refuses a checkout not on `main` (:50-56) and a dirty file (:65-67), which is exactly the state an agent mid-edit leaves — `syncspec` writes without committing by default and commits only on an explicit flag (the spec flow commits by path itself). Staleness token for the write: the hash of the raw file at read time (`wfedit/save.go:40-42`), carried as `spec_hash` on the question and used only for the compare-and-swap; the question's `rev` is a different thing (ADR 0005). Frontmatter writers preserve order, comments and unknown keys and rewrite only the touched key (`issue.go:777-842`); body round-trips are normalized (trailing blank lines, a single final newline, `issue.go:503,522-523`) — stated in specflow's contract. Beware the hidden comment block at the end of an issue file (`comment.go:12-13`): a spec file has none, but a writer must not invent one.

## 7. The clarify grammar: dark-factory vs the spec flow

Both tools put the round under `## Clarify`, one `### Q<n>.` heading per question, numbered options with the recommendation first, and an `**Answer:**` line; the differences are small and local to a regex set (`tracker/clarify.go:58-67`, `decisions.go:55-58`):

| | dark-factory (`tracker/clarify.go`, `decisions.go`) | the spec flow (gist `formats.md`, `SKILL.md`) | Ink Hub |
|---|---|---|---|
| option line | `1. **<label>** (recommended) <why>. Cost: <cost>.` (`optionLineRe` :60, `Cost:` required by the linter :335-383) | two to four options, costs, a recommendation that cites the work; no fixed `Cost:` token | accept both; render letters A/B/C on the page from option order |
| open answer | `**Answer:** —` | `**Answer:** —` | same |
| owner's answer | `**Answer:** <n> · <date> · owner: "<words>" (D-k)` (:427) | the answer in the user's own words, dated; the decision in the summary as `**D1 — <question>** → **A, <option>** — <owner, date>` and in the spec's record as `- D1 <question> → <answer> · [ADR]` | write the spec flow's form into the spec; keep dark-factory's form for issue files |
| assumed answer | `**Answer:** assumed[ <n>] — <reason>` (:48, :578-604) | `assumed — <reason>`; "you pick" = `assumed — user delegated, <date>` | same token, both parsed |
| decision line | `- **D-<n>** · <date> · <how>: <text>[, "<quote>"]` (`decisionLineRe` :55; `D-n` with a hyphen) | `D1 — <question> → A, <option> — <owner, date>` (no hyphen, an arrow, a letter) | the spec flow's; numbering per file by the max `D<n>` in `## Decisions` only (not the whole body, unlike `nextNumber` `decisions.go:456-464`) |

The brief's page zones (A/B/C boxes, an "otherwise" field, a sketch field) map onto option order, the free-text answer and the sketch PNG; `syncspec` writes the owner's words, never the OCR's raw text, which stays in `ocr.json`.

## 9. Risks and coupling (consolidated)

- **tmux degrades silently.** `agentrun.ListSessions` returns nil on error (`internal/agentrun/tmux.go:296-301`); approvals and send-backs land on disk with only a `NotificationError` when no pane answers (`handlers_issue_mutate.go:339-346`, `send_back.go:361-370`). Ink Hub makes delivery a first-class, retried slice (`deliveranswer`).
- **The question lifecycle is implicit today.** An open question is "the newest comment starts with `question:`" (`attention.go:77-83`); an answer is an unprefixed comment. Only the clarify round and `D-n` carry ids. The inbox needs its own Question/Answer records — which is the event log.
- **Approval is three non-atomic writes** (frontmatter, stats sidecar, comment: `handlers_issue_mutate.go:362-400`); the event log is the one source of truth and the spec file is a projection written by `syncspec`.
- **Delivery confirmation parses Claude Code's TUI frame** (`PromptPlace`, `tmux.go:530-553`) and limit regexes are pinned to CLI versions (`limits.go:34-53`): both break silently on a CLI update; adapters prefer the orchestrator's own status (herdr `agent.prompt --wait`, rex OSC 7501 `program_status_changed`).
- **No session id is recorded at launch** for a `claude -p --resume` adapter; the skill must capture it if the environment exposes one (to verify, §10).
- **`--wait` was removed on purpose** in v0.49.0 (`transition_check.go:41-58`: "stop and end your turn; the nudge resumes you"). The brief reintroduces an optional `ink ask --wait` for short decisions; the skill keeps the default asynchronous and names the Bash tool's timeout.
- **Lock files and temp files beside the document** (`<file>.lock` `issue.go:184`, `.<base>.tmp-*` `gitfile.go:160`) would be synced by a reader if they ever landed in `Ink/<project>/`; the WebDAV tree holds only published pages and uploads, never spec files.
- **`gitfile.Commit` refuses a dirty file and a non-main checkout** (`gitfile.go:50-67`); specflow writes without committing by default (§6.6).
- **Two data-dir conventions** in the fork: per-feature dirs under `<issues>/` for privacy (`outputs.go:206-210`, `memory.go:252-255`) vs repo-root dirs with a self-written `.gitignore` (`ci/state.go:163-172`, `yolo.go:82-86`). Ink Hub's data lives in the hub's data directory (ADR 0002), outside every repository.
- **Loopback-centric gates.** `publicRequest` treats any non-loopback Host as public (`identity.go:46-56`) and `hostAllowed` 421s unknown names (`origin.go:118-128`); the device-token gate replaces both the cookie (`owner.go:201-210`) and the Cloudflare path.
- **`nonceWriter` wraps every response** (`headers.go:202-204`), including JSON; not for a WebDAV server.
- **`privacy-guard.yml` fails every PR on a public repository** while `workflow.yaml` has `privacy: code: snapshots` (`workflow.yaml:918-924`); check before opening pull requests on the new repository.
- **`catalog-check` and the CHANGELOG `merge=union` contract** (`Makefile:60-61`, `.gitattributes:4`) are workflow-engine specific and will misfire once `sources:` paths move.
- **Format divergence** between dark-factory's and the spec flow's clarify and decision lines (§7): one grammar must be chosen before `syncspec` is built; the regex set is small and local.
- **Session ↔ issue matching is substring-based** (`tmux.go:73-91`): adapters key on an explicit agent ↔ question binding captured at `ink ask`.
- **The hidden comment block** at the end of issue files (`comment.go:12-13`) is lost by a naive round trip; spec files have none.
- **`numbering scans the whole body`** for `**D-n**` (`decisions.go:456-464`): a bold citation would bump the counter; Ink Hub numbers from `## Decisions` only.
- **A hardcoded path to the upstream author's machine** (`handlers_issue_mutate.go:218`: `$HOME/Work/michal-franc-agent/gh-app-token`) is read when importing GitHub issues; a config value in a fork.
- **Blank-import registrations** (`cmd/issue-cli/main.go:23-25`, `main.go:18`) mean removing `deptfamily`, `milestone`, `timeline` or `proof` silently drops health families and the proof gate; a *drop* commit of any of them runs `make test-legacy`.
